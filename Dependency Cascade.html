Modelling assumptions — confirm these
  • CONFIRM AGAINST THE PROGRAMME. Every date, duration and dependency in cascade-data.js is illustrative. The graph is the one place the programme lives — correct it there and the engine re-proves everything live.
  • Finish-to-start only: a test starts at the later of its planned start and every prerequisite's finish (+ lag). The gap between a prerequisite's planned finish and a successor's planned start is that edge's free float — it absorbs slip silently, which is exactly why small slips look harmless.
  • Slips extend completion: a slip of n days on an asset delays its finish by n days; the forward pass propagates the consequence, never more, never less. Multiple simultaneous slips compose.
  • Zero-float edge by design: the thermal run (MECH L4) cannot start before integrated power (ELEC L4) proves — that edge carries no float, so ELEC L4 is always the sharpest lever.
  • H2C → PFHO move together: the 11-day punch-clear window between them is a lag with zero float, mirroring how the programme treats the pair.
  • Calendar days, not working days — weekends are not modelled. Cost of delay is a flat £185k/day applied to PFHO movement only.
